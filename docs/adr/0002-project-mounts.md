# 0002: Project Mounts — worktree-копии для RW, событийные напоминания

`/chat-project-mount` монтирует каталог (по умолчанию ctx.cwd) в подключённую сессию по фиксированному гостевому пути `/workspace/project`; режимы unmount/ro/rw, состояние персистится в `channel.gondolin.mounts`. Для git-репозитория extension создаёт на хосте worktree (в каталоге канала, `channels/<c>/worktrees/<slug>`, через `git worktree add`) и маунтит его в VM; не-git каталог биндится как есть, без копии. Режимы: **ro** = read-only bind исходника, **rw** = worktree-копия — правки агента не трогают исходный проект до ручного merge человеком на хосте.

## Контекст сессии

Информация о маунтах подаётся событийно, а не в каждом ходе: при mount/unmount в контекст сессии добавляется напоминание (reminder), и оно повторно инжектится после compaction, чтобы не потеряться. Формат: путь в VM + режим (RO/RW) + источник на хосте + краткая RW-инструкция («правки идут в worktree-копию, исходник не трогается; коммить в ветку»).

## Живые изменения конфигурации

Межпроцессного IPC нет. Изменение маунтов применяется: (а) в том же процессе — сразу, перезапуском sandbox (`applyAndRestart`); (б) в живом detached-воркере — только после его перезапуска (`/chat-spawn-all --restart`), поэтому `/chat-project-mount` предупреждает о живом воркере. Allowlist remoteMcp воркер перечитывает из конфига в начале каждого remote-хода (ADR 0001), перезапуск для него не нужен.

## Consequences

- Worktree никогда не удаляется автоматически при unmount: в нём могут быть незакоммиченные правки; чистка устаревших worktrees — вручную.
- Новый ход воркера не содержит маунт-инфу, если с последнего напоминания ничего не менялось и compaction не было.
- Альтернатива «rw = прямой bind хост-директории» отклонена: правки агента попадали бы в проект незамеченными; worktree даёт явную точку merge.
