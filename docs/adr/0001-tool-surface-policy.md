# 0001: Инструментальная поверхность подключённых сессий и remote-ходов

Подключённая сессия (воркер канала или TUI после /chat-connect) исполняется в VM Gondolin, и доступ к хосту возможен только через явно разрешённые поверхности. Решили: (1) при /chat-connect весь набор инструментов сессии ограничивается VM-инструментами (read/write/edit/bash), chat_* и codemode — без escape hatch, возврат полного набора при /chat-disconnect; (2) MCP-инструменты управляются единым allowlist `accounts.<id>.remoteMcp` в config.json: по-инструментно, только явные имена, правило действует на всю подключённую сессию (интерактив и remote-ходы alike).

## Considered Options

- **Enforcement раздельный по exposure.** Direct-инструменты (bg, subagent, хостовый MCP) убираются через `setActiveTools` — это заодно убирает их из codemode-песочницы (список script-callable строится живым геттером `_getCallableTools()`). Codemode/deferred-инструменты из песочницы неубираемы by design — их единственный барьер это hook `tool_call`, который срабатывает и на вложенных вызовах из codemode-скриптов. Следствие: одна функция «разрешённого набора» питает и `setActiveTools`, и hook — два механизма, один источник истины.
- **Allowlist в /shared** — отклонено: /shared смонтирована в VM с записью, агент смог бы сам себе выдать MCP. config.json правится только с хоста.
- **Wildcard `server: "*"`** — отклонено: новый инструмент сервера получал бы доступ молча, вразрез с по-инструментной гранулярностью.
- **Escape hatch** (временно вернуть хостовые инструменты в подключённой сессии) — отклонено: строгая модель проще и безопаснее.
- **Пикер /chat-skills** — отклонён: скиллы берутся все из единого источника `/shared/.pi/skills`, наполнение — на стороне человека.

## Consequences

- Интерактивная работа в подключённой TUI-сессии ограничена тем же набором, что и remote-ходы; хостовая работа ведётся в отдельном локальном сеансе без connect.
- Появление нового инструмента у разрешённого MCP-сервера не даёт доступа автоматически — требуется явная правка config.json.
- Ограничение: MCP resource-инструменты (`list_mcp_resources`, `list_mcp_resource_templates`, `read_mcp_resource`) в подключённой сессии недоступны — allowlist адресует только инструменты серверов (`mcp__<server>__<tool>`).
- Ограничение: имена MCP-инструментов санитизируются до `mcp__<server>__<tool>` (все символы вне `[A-Za-z0-9_]` → `_`), поэтому разные пары сервер/инструмент могут схлопнуться в одно имя; allowlist в этом случае пускает оба — точность по-инструментного контроля ограничена санитизацией pi.
